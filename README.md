## Requirements

Python ≥ 3.10, the packages in `requirements.txt` (including a CPU build of PyTorch for `kt_dkt.py` and
`kt_attn.py`, `pyarrow` for the EdNet files and `krippendorff` for `agreement.py`) and
`bsdtar` (libarchive) to read the RAR archive. Tested on Ubuntu 24.04, Python 3.13, 2 CPU cores, 7 GB RAM.
The base pipeline takes about 15 minutes, the DKT-based analyses about 20 minutes, SAKT and AKT on Junyi
about 2 hours each, the controls and the KT training-length check about 45 minutes, and `run_extended.sh` about 6 hours; the graph-propagated estimator takes about 30 minutes per dataset and the data-regime study about 10 hours on Junyi and 3 hours on XES3G5M, and the extended study about 3 hours more on Junyi (measured on 2 CPU cores and 8 GB RAM; timings in the shell scripts).

## Reproduce

    pip install -r requirements.txt
    bash run_all.sh /path/to/junyi.rar
    bash run_extended.sh /path/to/skill_builder_data_corrected_collapsed.csv /path/to/kt1_0.parquet /path/to/questions.parquet /path/to/XES3G5M.tar.gz
    cd code && python graph_estimator.py full && bash data_regime.sh
    python graph_estimator_replication.py full /path/to/xes3g5m_prep && bash data_regime_replication.sh /path/to/xes3g5m_prep
    bash data_regime_extended.sh && python graph_estimator_recalibration.py
    python data_regime_summary_basic.py data/regime /path/to/xes3g5m_prep/regime
    python data_regime_summary.py data/regime /path/to/xes3g5m_prep/regime
    bash data_regime_relation_control.sh && python data_regime_relation_summary.py data/regime /path/to/xes3g5m_prep/regime

The script verifies the download, converts the log, runs every analysis in `code/`, redraws the figures and
runs `compare_outputs.py`, which compares every regenerated number with `expected_outputs/` (relative
tolerance 1e-3) and prints `ALL OUTPUTS MATCH` or the list of differences. `run_extended.sh` compares the
replication outputs with `replication/` in the same way. DKT, SAKT and AKT are trained with fixed seeds;
PyTorch does not guarantee bit-identical results across hardware and library versions, so values that depend
on these models may differ in the third or fourth decimal on another machine. Their training logs
(`kt_sakt_junyi.json`, `kt_akt_junyi.json` in `supplementary_outputs/`; `out_dkt.json`, `kt_*.json` in
`replication/`) are kept for reference and not compared.

## Note on the comparison tolerance

`compare_outputs.py` uses |expected − regenerated| ≤ TOL × max(1, |expected|) with TOL = 1e-3 by default,
that is, an absolute tolerance of 1e-3 for values below 1. Five-decimal AUC increments (for example −5.39e-05
for the primary score) are therefore not tested at the default; run `python compare_outputs.py 1e-6` inside
`code/` after a complete run for a stricter check. Regenerating the archived numbers shows that the code
reproduces them; it is not an independent check of the scientific correctness of the analyses.

## Conventions

- Crowd pair (Exercise_A, Exercise_B) is read as Exercise_B → Exercise_A.
- Q is computed on ratings rescaled to [0, 1]; Q_min = 0.80 was selected on validation data.
- Per-learner split: training segment < 60 %, validation 60–80 %, held-out ≥ 80 % of each learner's attempts.
- All estimators (population prior, BKT, cold-start logistic KT, DKT, SAKT, AKT) are fitted on training
  segments only.
- All learner-bootstrap intervals in `out_benchmark.json` share one set of 300 resampling weights (seed 2027).
- Seeds are fixed inside each script.

- A complete clean run of `run_all.sh` on 2026-11-08 regenerated every archived number within tolerance except five
  values of `out_benchmark.json` that count failures flagged at the 10 % alert budget for B1RK models (differences
  of at most 0.013 failures per 1,000 cases), which depend on the order of near-tied DKT-based predictions at the
  budget boundary; all AUC values matched (`supplementary_outputs/run_log_20261108.txt`). The values at the 10 %

- AKT is the distance-decay variant without the Rasch embedding; on Junyi it was trained on 35 % of the training
  pieces for one epoch.
- `kt_attn.py` answers all queries of one row together (identical predictions to one-at-a-time queries, maximum
  difference 6e-8 in a check), which makes the 22 million XES3G5M queries feasible on a CPU.
- `compare_outputs.py` accepts an expected folder, a generated folder and a file list.
